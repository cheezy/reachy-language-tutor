# Stride Configuration

Hooks run on this machine at four points in a task's life. Each line below runs as its own
command, in order, from the repository root. A **blocking** hook stops the workflow if any
line exits non-zero.

Every command names the Python interpreter explicitly rather than relying on an activated
virtualenv, which is the same convention as `docs/SETUP.md`. **If your virtualenv is not at
`~/dev/reachy/reachy_mini_env`, change these paths.**

## before_doing

Executes before starting work on a task (blocking, 60s timeout).

```bash
echo "Starting $TASK_IDENTIFIER: $TASK_TITLE"
git status --short
$HOME/dev/reachy/reachy_mini_env/bin/python -c "import reachy_language_tutor; print('app imports OK')"
```

The import check is the cheap version of "is my environment still sane" — it catches a broken
or half-upgraded virtualenv now, rather than after you have written code against it.

There is deliberately **no `git pull`** here. This repository has no remote yet, so a pull
would fail and block every task. Add `git pull origin main` back once GitHub is set up.

## after_doing

Executes after completing work (blocking, 120s timeout).
If this fails, task completion should fail.

```bash
$HOME/dev/reachy/reachy_mini_env/bin/ruff format --check reachy_language_tutor/src
$HOME/dev/reachy/reachy_mini_env/bin/ruff check reachy_language_tutor/src
$HOME/dev/reachy/reachy_mini_env/bin/python -m pytest reachy_language_tutor -q
```

This is the real quality gate. In order:

1. **`ruff format --check`** — fails if any file is not formatted to the project's style. It
   only reports; run the same command without `--check` to actually reformat.
2. **`ruff check`** — the linter. Catches unused imports, undefined names, and similar.
3. **`pytest`** — the test suite: 223 tests, about 4 seconds.

Both tools are already configured in `reachy_language_tutor/pyproject.toml` and are installed
with `pip install pytest pytest-asyncio "ruff==0.15.20"`.

> **Why the suite ignores seven files.** They come from the upstream conversation app and test
> profile *switching*. This app sets `config.LOCKED_PROFILE`, which deliberately disables
> switching, so 31 of their tests fail by design rather than by regression. The exclusions live
> in `[tool.pytest.ini_options]` in the app's `pyproject.toml`, not here, so a plain `pytest`
> behaves the same way for a human as it does for this hook. Revisit if the app ever stops
> locking its profile.

## before_review

Executes when task enters review (blocking, 60s timeout).
If this fails, task completion should fail.

```bash
echo "$TASK_IDENTIFIER ready for review: $TASK_TITLE"
git status --short
```

No pull request is created. There is no GitHub remote yet, so `gh pr create` would fail and
block the task. Once a remote exists, this is where that command belongs.

## after_review

Executes after review approval (blocking, 60s timeout).
If this fails, mark_reviewed should fail.

```bash
echo "$TASK_IDENTIFIER approved: $TASK_TITLE"
```

Nothing to deploy. The app is published to Hugging Face manually with the app assistant, and
that is not something to trigger automatically on every approved task.

## after_goal

Executes when a goal's final child task completes (blocking, 60s timeout).

```bash
echo "Goal complete: $TASK_TITLE"
git status --short
```

The canonical job for this hook is publishing the goal's work to the remote — the Stride
server flips the goal to Done but never publishes anything itself. This repository has no
remote yet, so there is nothing to send and the usual command would fail and block the goal.

**Add the publish step here once GitHub is set up**, or goals will reach Done with their
work never leaving this machine.
